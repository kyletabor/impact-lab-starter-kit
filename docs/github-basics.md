# GitHub in plain words

GitHub is a shared folder for code that remembers every saved version. Your submission is a link to your team's public GitHub repo, so everyone needs the basics.

## Five words you'll hear

| Word | Plain meaning |
|---|---|
| **Repo** | Your project folder on GitHub |
| **Clone** | Copy the repo to your laptop |
| **Commit** | Save a snapshot with a note about what changed |
| **Push** | Send your snapshots up to GitHub |
| **Pull** | Get your teammates' snapshots down to your laptop |

## You don't have to type git commands

Claude Code runs git for you. Just ask:

```text
commit what we have with a clear message
```

```text
push our work to GitHub
```

```text
pull my teammates' latest changes
```

```text
what files have I changed?
```

The first push may ask you to sign in to GitHub. Follow the prompts, or ask Claude Code, or ask a mentor.

## Working as a team without stepping on each other

- **Split by file.** One person on the page, one on the data, one on the README.
- **Pull before you start, push when it works.** Say "pull, then push our work" every hour or so.
- **Got a conflict?** That means two people changed the same lines. Ask Claude Code: `help me resolve this merge conflict`.

## Before you submit

- [ ] The repo is **Public** (repo **Settings**, then **General**, then **Danger Zone**, then **Change visibility**)
- [ ] No `.env` file or API key is in the repo
- [ ] The README tells a stranger how to use it (`/ship` writes this with you)
- [ ] Your latest work is pushed. Check the repo page in your browser
